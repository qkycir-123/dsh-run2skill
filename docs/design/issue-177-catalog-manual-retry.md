# 一次手动重试检索 Design

状态：依据负责人已确认的有界失败恢复方案实施；对应 #177，来源 #174。

## 范围与错误分类

只恢复已有 Skill 检索中的一个失败目录分页。官方 DSH 0.2.0-rc.2 的 LlmFailure 提供 code / status；仅 RATE_LIMIT + 429，或 SERVER + 500 / 502 / 503 / 504 / 529，归为已确认的临时模型失败。保留已完成检测、成功分页与第一次失败诊断。没有状态事实的断流、未知结果、认证/权限、无效输出、输入不完整、目录或路径变化继续停止。本切片不增加其他阶段的通用重试，也不自动重试。

## 授权与调用账本

每个 ExperienceIntent 最多保存一个可选 catalogRetry 授权，绑定失败 callId、授权 revision、当前 action 身份、scope digest 和时间。默认没有授权，历史数据无需迁移。人工点击时持全局变更锁，验证当前作用域、仍存在的证据、无 purge journal、最新 action 和 revision，然后先持久化授权并进入 RECALLING，最后唤醒流水线。

重复请求核对原授权和当前可见性后返回同一已接受事实，不再消耗授权。重试 callId 由原失败 callId 和授权 revision 派生；第一次 FAILED 调用保留在账本中。Schema 只允许这一个有证明的附加调用，完成判定使用成功分页加授权替代页，不把失败调用伪装成成功。

## 重新核验与恢复

执行前重新取得完整目录并比对原扫描计划、路由、策略和输入摘要。目录变化则停止，不复用失效分类；目录保持一致时跳过已成功分页，只重试失败页，再按原流程完成其他尚未开始页。覆盖判断与生成继续通过原有安全门，Proposal 仍需人工审核。

预留调用先落盘；进程重启发现 RESERVED 将其记为 OUTCOME_UNKNOWN，不重放。再次确认临时失败时授权已消耗，页面只保留诊断及关闭入口。计划最多原页数加一条调用，原有页数与输入预算保持。

## 页面

说明“已有 Skill 检索暂时失败”，保留各阶段完成状态。仅 Host 提供 RETRY 动作时显示“重试检索一次”；不使用内部错误码作为正文，也不要求重新发起会话。重复点击由现有 pending 状态与 Host 授权共同约束。

## 验收

- 官方结构化终止错误和抛出的 LlmFailure 正确分类，错误消息不持久化；未知/确定性错误不能重试。
- 一次人工授权、并发/重复请求、重启和两 worker 竞争均无重复模型调用。
- 成功分页、检测结果、第一次失败诊断保留；完成状态能继续覆盖判断。
- 目录变化、范围变化、purge、再次失败和崩溃未知结果停止。
- Schema 拒绝没有对应临时失败和授权回执的附加调用。
- 页面按钮及提示符合真实 Host 动作；typecheck、lint、完整测试和直接相关的官方 DSH 错误协议探针通过。
